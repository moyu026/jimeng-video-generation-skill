# Planning 模块

## 何时读取

当用户要求生成即梦视频脚本、技术发布短视频规划、分镜、配音稿、AI 视频 Prompt，或完整端到端流程的第一步时读取。

## 输入

- 发布稿 / 产品文档 / Markdown / 技术文章
- 截图、录屏、架构图、流程图、机制图等素材
- 用户指定的视频目标、受众、比例、风格；未指定时默认 16:9、个人技术分享风格

## 输出

规划阶段只输出：

```text
video-plan.md
narration.md
shot-list.md
```

不输出最终 SRT，不调用即梦 / TTS / 录屏工具。

## 工作步骤

1. 捕获用户意图：确认是完整规划还是单项 Prompt / 单项脚本。
2. 提炼产品叙事骨架：核心功能、用户痛点、旧方式不足、一句话定义、核心变化、核心能力、Wow Moment、适用场景、边界判断、价值升华。
3. 技术观点提取：关键机制、性能收益、边界判断优先参考原文，保留核心术语，不改成泛营销话术。
4. 组织视频结构：默认 Hook / What / How / Future 四段式，时长根据素材复杂度和复用片段动态决定，总时长控制在 150 秒以内。
5. 判断素材类型：AI 视频、原图复用 + 统一背景图、HTML 动态图解、原始图片复用、原始视频复用、后期包装。
6. 若素材包含原图 / 架构图 / 流程图 / 机制图 / 产品截图，且用户未说明处理方式，必须先询问两个分支：
   - 复用原图 + 生成统一背景图
   - 将原图按原结构重绘为 HTML 动态图解
7. 为 AI 视频镜头编写镜头内时间轴 Prompt。

## AI 视频 Prompt 规则

每个 AI 视频镜头必须包含：

- 镜头总时长
- 整体画面设定
- 逐 1–2 秒画面变化
- 镜头运动方式
- 结尾画面状态
- 风格要求
- 禁止内容

禁止内容固定包含：

> 禁止生成任何可读文字、字母、Logo、真实代码、品牌标识、真实人物或人物背影。所有文字、代码和 UI 标签都必须用抽象线条、空白卡片、不可读图标块、伪代码形状和示意图形表达，文字内容统一由后期添加。

## 完成标准

- `video-plan.md` 讲清楚视频目标、受众、叙事骨架、总时长估计、章节结构。
- `narration.md` 是可直接配音的自然口播稿，专业准确，不含非口播标题说明。
- `shot-list.md` 每个镜头都有 ID、时间估计、素材类型、画面设计、配音映射、后期建议和状态。
- 如果使用 AI 视频，Prompt 具体、可见、可动、可生成。
- 如果包含原图，已经明确用户选择的原图处理分支。

## 失败 / 退化路径

- 素材不足以判断产品 / 功能对象：追问。
- 用户只要求单项 Prompt：只输出 Prompt，不生成完整规划文件。
- 用户要求 SRT：说明最终 SRT 应在音频确认后生成；若只是预览字幕，可明确标记为“草稿字幕”。

## 自检清单

- [ ] 是否没有在规划阶段生成最终 SRT？
- [ ] 是否体现技术专业度，而不是泛娱乐口播？
- [ ] 是否因为压时长删掉了必要机制解释？
- [ ] 是否明确区分素材类型？
- [ ] 是否展示一个最强 Wow Moment？
- [ ] AI Prompt 是否包含逐 1–2 秒时间轴？
- [ ] 原图处理方式是否已经确认？
