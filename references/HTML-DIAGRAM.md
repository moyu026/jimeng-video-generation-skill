# HTML Diagram 模块

## 何时读取

仅当用户提供架构图 / 流程图，且该结构无法用即梦清楚表达时使用本模块；整条视频最多规划 3 个 HTML 录屏。满足条件后，用户可选择“将原图按原结构重绘为 HTML 动态图解”，或要求调试已有 HTML 图解。

本模块只负责：

```text
原图 / 架构图 / 流程图 / 机制图 / 产品截图
→ 按原结构重绘为单文件 HTML 动态图解
→ 人工打开页面验证效果
```

验证通过前，不进入 HTML Recording 模块。

## 输入

- 原图 / 架构图 / 流程图 / 机制图 / 产品截图。
- 原文中对该图的上下文说明。
- `shot-list.md` 中对应镜头描述，尤其是：原图来源、HTML 输出、保留结构、动画顺序、动画时长、录屏时长、录屏输出。
- 用户反馈截图或文字反馈（调试阶段）。

## 输出

```text
assets/html/<diagram-id>.html
```

同时需要在回复或 `asset-manifest.md` / `edit-guide.md` 中记录：

```text
HTML Review 状态：needs-human-review / approved / needs-fix
人工验证结论：<待用户确认 / 已确认 / 需修改点>
```

## 工作步骤

1. **识别原图类型**：分层结构、金字塔、流程图、架构图、关系网络、对比图、指标说明图、产品截图标注图。
2. **提取原图结构**：主标题、模块、层级、位置关系、箭头 / 连线 / 流向、说明区、底部价值句、图例、编号、强调色。
3. **确认保留策略**：默认保留原图结构和原图文字信息；只在用户明确要求时压缩、改写或删减文字。
4. **设计 HTML 版式**：使用单文件 HTML/CSS/JS，每个模块为独立 DOM；`.stage` 使用用户确认的横屏 `16:9` 或竖屏 `6:7`，布局基于 `.stage` 内容区域。
5. **实现可控动效**：模块按叙事逻辑出现，箭头 / 连线按流向出现，关键模块可扫光、描边、高亮或轻微放大。
6. **加入 Replay 控制**：默认隐藏 Replay，支持键盘按 `R` 重播，右下角 hover 才弱显示按钮。
7. **自查后交付 HTML**：交付文件路径、说明动画顺序、列出已自查项。
8. **强制人工验证**：每张图的 HTML 生成后必须停下，请用户或人工审阅浏览器渲染效果。人工未确认前，不能进入录屏。
9. **反馈调试**：如果人工验证发现问题，优先局部修改 CSS 和少量 DOM，不重写整体结构；每次修改后再次进入人工验证。

## 布局规范

- 横屏 stage 使用 `16:9`；竖屏 stage 使用 `6:7`。推荐模板通过 `?orientation=portrait` 切换竖屏，未传时为横屏。
- 所有布局基于 `.stage` 实际内容区域，不基于显示器物理分辨率硬编码。
- 关键内容必须落在已确认比例的安全区内。页面底部至少预留 18% 字幕安全区；标题、节点、箭头、图例、说明文字和关键动画不得进入该区域。
- 使用 `--subtitle-safe-height:18%` 管理字幕安全区；普通审核模式显示参考线，`?record=1` 时隐藏参考线。
- 横向流程图、阶段流、模块流必须使用 CSS Grid 管理模块和箭头。
- 箭头 / 连接线必须作为独立 Grid 列或 Grid 行，例如：`模块 | 箭头 | 模块 | 箭头 | 模块`。
- 不要让模块使用 Grid，而箭头脱离布局后用 absolute + left 百分比反复猜位置。
- 金字塔 / 分层图可使用 absolute 定位，但仍必须基于 stage 内部坐标。
- 关系网络图必须统一坐标系统，节点和连线层级明确。
- 产品截图类图解可以复刻主要 UI 区块，但避免无意义像素级临摹；重点保留结构、流程和可解释区域。

## 信息完整性

- 默认保留原图文字信息，不主动压缩、改写或删除关键说明。
- 不允许依赖 `overflow:hidden` 裁掉关键文字；`overflow:hidden` 只能用于扫光、光效、装饰元素。
- 文字溢出时优先：扩大模块或说明区域、调整 Grid 比例、减小字号、减小 padding、调整行距、增加模块高度。
- 如果原图文字非常密集，优先通过局部放大、分层出现、分组展示解决，而不是直接删减。
- 只有用户明确允许“精简 / 压缩文字”时，才压缩文案或删减 bullet。
- 不默认额外添加 takeaway 标签项，除非原图本身已有或用户明确要求。

## 动画规范

- 动画服务于解释，不为了炫技牺牲结构可读性。
- 默认动画顺序：标题 / 背景框 → 主模块 → 子模块 → 箭头 / 关系线 → 关键高亮 → 终态全图。
- 架构图按数据流或调用链出现；流程图按时间顺序出现；分层图按底层到顶层或原图逻辑出现；关系网络图按核心节点到外层节点出现。
- 每个图解必须有稳定终态；动画完成后 DOM 保持终态。
- 在 `.stage` 上用 `data-animation-duration="<秒数>"` 声明动画本身的时长。
- `shot-list.md` 同时记录动画时长 A 和录屏时长 A+1 秒；额外 1 秒由 `record_html_with_ffmpeg.py` 用于保留终态。
- 避免无限循环动画影响录屏；装饰性呼吸光可以保留，但不能干扰主要信息。

## Replay 控制项

- Replay 不应影响录屏构图。
- 默认隐藏或极弱化。
- 必须支持键盘按 `R` 重播。
- 鼠标 hover 到右下角时才淡淡显示 Replay。
- 人工验证和录屏前都应测试：页面打开后动画能播放，按 `R` 后能从头重播。

推荐实现见 `templates/html-diagram-template.html`。

## 关系网络图 / 多箭头图规则

- 统一坐标系统；若节点是 HTML DOM，关系线也优先使用 HTML/CSS 线段。
- 多箭头关系网络图不优先使用 SVG marker；如果使用 SVG，必须确保 viewBox、坐标、marker 大小和缩放一致。
- 连线从节点边缘到节点边缘，不穿过节点中心。
- 箭头头部停在节点外侧或边缘，不能压住节点文字。
- 为多条边分配不同通道，避免挤在中心区域。
- 区分实线、虚线、细线语义。
- 箭头头部建议 8–12px，线条层级低于节点。
- 不要为同一对节点重复绘制多余边。

## 强制人工验证 Checkpoint

每张图生成 HTML 后必须停下，输出类似确认语：

```text
HTML 图解已生成：assets/html/<diagram-id>.html
当前状态：needs-human-review

请人工打开该 HTML 并检查：
1. 原图结构和层级是否保留？
2. 关键文字是否完整、无遮挡、无裁切？
3. 模块位置、箭头方向、连线语义是否正确？
4. 已确认的 `16:9` 或 `6:7` 画面边缘是否安全，底部 18% 字幕安全区是否没有关键内容？
5. 动画顺序是否符合技术逻辑和配音节奏？
6. 按 R 是否可以从头重播？
7. 右下角 Replay 是否默认不干扰画面？

人工确认通过后，才能进入 HTML Recording 模块。
```

人工验证结论写法：

```text
HTML Review: approved
Reviewer: <用户 / 人工审阅者>
Notes: <通过 / 需修改点>
```

如果用户反馈问题，状态改为
eeds-fix`，修复后再次回到
eeds-human-review`。

## 反馈调试规则

- 优先局部修改，不重写整体。
- 保持原图结构稳定。
- 保持已有动画逻辑稳定，除非用户明确指出动画节奏问题。
- 优先解决文字完整显示、箭头遮挡、模块裁切、底部说明被挡、动画不同步。
- 每次修改后说明改动点，并提示刷新页面或按 `R` 重播。
- 每次修改后都必须重新人工验证，不允许“修完直接录屏”。

## 完成标准

- HTML 是单文件，可直接浏览器打开和录屏。
- 保留原图信息结构和版式关系。
- 文字完整显示，没有关键内容被裁切或遮挡。
- 流程图箭头纳入 Grid；关系网络图连线不压住节点文字。
- 动画顺序清晰，终态稳定。
- Replay 默认隐藏，按 `R` 可重播。
- 底部 18% 字幕安全区没有标题、节点、箭头、图例、说明文字或关键动画。
- `.stage` 已声明准确的 `data-animation-duration`。
- 已经过人工验证并记录 `HTML Review: approved`。

## 失败 / 退化路径

- 原图信息过密且无法完整重绘：建议改用“原图复用 + 统一背景图”。
- DOM 结构无法表达原图关系：允许重构 DOM 或局部使用 SVG / Canvas，但需说明原因。
- 浏览器渲染与预期不一致：先做人工截图反馈，再局部修复。
- 人工验证多次不通过：暂停录屏，回到结构提取和版式设计阶段。
- 用户明确要求视觉创新：仍需保留原图关系语义。
